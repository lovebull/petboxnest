# 美国 D2C/B2C 独立商城 PRD 与 MVP 验收标准

> 文档状态：待评审
> 版本：0.1
> 目标市场：美国
> 商业模式：单品牌、单经营主体、自营实物商品
> 默认语言与币种：English / USD
> 技术基线：Next.js + Medusa v2 + PostgreSQL + Redis

## 1. 文档目的

本文件定义首个可上线版本（MVP）的产品目标、用户范围、功能边界、业务规则和验收标准。通过本文件后，新增需求原则上进入后续版本，避免首期范围持续膨胀。

## 2. 产品目标

为美国消费者提供一个可信、快速、适合移动端的品牌独立商城，使用户能够完成从发现商品到支付、收货、申请退货的完整闭环，并使内部运营人员能够管理商品、库存、订单、促销和售后。

### 2.1 MVP 成功定义

MVP 上线时必须满足：

- 消费者可使用美国地址完成游客结账。
- 消费者可使用 Stripe 支付；PayPal 作为建议纳入项，若排期冲突可在 Beta 后补充。
- 系统能正确处理支付成功、失败、取消和重复 Webhook。
- 系统能按 SKU 管理库存并避免正常并发下的超卖。
- 运营人员可完成商品上架、订单发货、取消和退款。
- 消费者可收到订单确认、发货和退款邮件。
- 核心页面具备基础 SEO、移动端适配和无障碍能力。
- 生产环境具备日志、告警、备份和关键操作审计。

### 2.2 建议跟踪的业务指标

MVP 不承诺具体商业数值，但上线后应能采集：

- Sessions
- Product view rate
- Add-to-cart rate
- Checkout start rate
- Checkout completion rate
- Payment failure rate
- Average order value
- Refund and return rate
- Repeat purchase rate
- Revenue by channel / campaign

## 3. 用户角色

### 3.1 访客

- 浏览、搜索和筛选商品
- 查看商品详情、库存和预计配送信息
- 加入购物车
- 使用游客身份结账
- 接收订单邮件

### 3.2 注册客户

除访客能力外：

- 登录和退出
- 管理个人资料和地址
- 查看订单历史及详情
- 发起符合条件的退货申请

### 3.3 运营人员

- 管理商品、分类、价格、图片和上下架
- 查看订单、客户和库存
- 创建促销码
- 更新订单履约状态

### 3.4 客服/售后

- 查询订单
- 审核退货
- 发起全额或部分退款
- 记录售后原因与备注

### 3.5 管理员

- 管理员工账号和角色
- 管理支付、物流、税务等商店配置
- 查看审计日志

## 4. MVP 范围

### 4.1 Storefront

| 购物车 | 增删改数量、优惠码、预估小计、库存复核 |
| Checkout | 联系方式、美国地址、配送、税费、支付、订单确认 |
| 账户 | 注册、登录、重置密码、资料、地址、订单列表 |
| 售后 | 订单详情、退货申请入口、退款状态 |
| 内容页 | About、Contact、FAQ、Shipping、Returns、Privacy、Terms |
| SEO | Metadata、canonical、sitemap、robots、结构化数据 |
| Analytics | GA4 电商事件、广告像素的基础事件 |

### 4.2 Admin

| 模块 | MVP 内容 |
|---|---|
| 商品 | Product、Variant、SKU、图片、价格、重量和尺寸 |
| 分类 | Collection / Category 的创建、排序与可见性 |
| 库存 | 按 SKU 查看和调整可售库存 |
| 订单 | 搜索、详情、状态、支付、发货、取消 |
| 履约 | 录入或生成运单、Tracking、部分发货 |

| 促销 | 固定金额、百分比、使用期限和最低消费 |
| 配置 | 商店信息、邮件发件人、物流与税务配置 |
| 权限 | Admin、Operations、Support 三类基础角色 |
| 审计 | 商品、库存、订单和退款关键操作记录 |

- 订阅制商品
- 积分、VIP 等级和推荐返利
- Gift Card / Store Credit

- AI 推荐和个性化定价

- 完整拖拽式页面搭建器
- 多语言、多国家正式销售
- 电话下单和 POS

## 6. 核心业务规则

### 6.1 商品与库存

- 库存最小管理单元是 Variant/SKU。
- 已下架商品不可新加入购物车；购物车内已有商品在结账时再次校验。
- `available_quantity = stocked - reserved - allocated`，具体字段可由 Medusa 内部模型映射。
- 下单过程中创建短时库存预留；支付失败、取消或超时后释放。
- 已发货订单取消时，不自动恢复库存；必须走退货或人工处理。
- 退款时由操作人员明确选择是否补库存。

### 6.2 价格

- 所有首期销售价格以 USD 保存和展示。
- 商品页价格默认不含 Sales Tax。
- Cart 中展示商品小计；确认收货地址后显示预计或最终税费。
- 服务端重新计算订单金额，不能信任浏览器传入的价格。
- 促销和税费的计算顺序由 Medusa/税务 Provider 固化并通过测试覆盖。

### 6.3 优惠

MVP 支持：

- 百分比折扣
- 固定金额折扣
- 最低订单金额
- 生效/失效时间
- 总使用次数
- 每位客户使用次数

MVP 不支持自动叠加多个优惠。默认一单一个 Promo Code。

### 6.4 支付

- Stripe 为主支付渠道。
- 订单支付状态以服务端验证的 Provider 结果/Webhook 为准。
- 每个 Webhook Event ID 只能成功处理一次。
- 客户关闭页面或网络中断后，系统仍能通过 Webhook 恢复正确订单状态。
- 不在本系统保存完整卡号或 CVC。
- 支付失败不能扣减最终库存，也不能进入待履约状态。

### 6.5 订单

建议统一状态语义：

```text
Cart
  -> Pending Payment
  -> Paid
  -> Fulfillment Pending
  -> Partially Fulfilled / Fulfilled
  -> Delivered（若物流 Provider 可确认）

异常分支：
Pending Payment -> Payment Failed / Canceled / Expired
Paid -> Canceled + Refunded（仅未发货且符合策略）
Fulfilled -> Return Requested -> Returned -> Partially/Fully Refunded
```

### 6.6 配送

- 首期只接受美国境内可服务地址。
- 物流报价由 Shippo 或 EasyPost 返回；不可用时给出明确提示，不静默使用错误价格。
- 支持 Standard 与 Expedited，实际服务名称映射为统一展示名称。
- Free Shipping 作为可配置的订单金额阈值。
- Tracking Number 必须与 Shipment 关联，并在发货后邮件通知客户。

### 6.7 税费

- 根据美国收货地址和商品 Tax Code 计算。
- Stripe Tax 为首选实现。
- 税务登记、Nexus 判定和申报不由商城软件自动替代。
- 退款必须保留商品金额、运费、税费各自的退款明细。

### 6.8 退货和退款

默认产品策略，最终需经营方确认：

- 签收后 30 天内可发起退货。
- 商品需保持可再销售状态。
- Final Sale 商品不可退。
- 原支付方式退款。
- 原始运费默认不退；质量问题可由客服例外处理。
- 退货运费由谁承担做成策略配置，不写死在代码中。

## 7. 功能验收标准

### 7.1 商品浏览

- [ ] 用户可从首页进入 Collection。
- [ ] Collection 只展示已发布且当前销售渠道可见的商品。
- [ ] 用户可按价格、上新等既定规则排序。
- [ ] 筛选和排序状态可反映在 URL 中，页面刷新后不丢失。
- [ ] 商品无库存时显示 Sold out，且不能加入购物车。
- [ ] 商品 Metadata、canonical 和 Product JSON-LD 正确输出。

### 7.2 商品详情

- [ ] 切换 Variant 后价格、SKU、库存和图片按配置更新。
- [ ] 未选择所有必选规格时不能加入购物车，并显示字段级提示。
- [ ] 数量不能小于 1，不能超过可售库存或单笔上限。
- [ ] 图片支持键盘操作、替代文本和响应式加载。

### 7.3 购物车

- [ ] 游客 Cart 在同一浏览器会话中可持续保存。
- [ ] 修改数量后服务端重新计算金额。
- [ ] 删除最后一个商品后显示 Empty Cart 状态。
- [ ] 无效、过期或不满足条件的 Promo Code 返回可理解的提示。
- [ ] 进入 Checkout 前再次校验商品状态、价格和库存。

### 7.4 Checkout

- [ ] 可用美国地址完成游客结账。
- [ ] State 使用标准两位州代码保存。
- [ ] ZIP Code、Email 和必填字段有前后端校验。
- [ ] 地址确认后展示可用配送方式和税费。
- [ ] 用户提交支付时按钮防重复点击。
- [ ] 支付成功后只创建一个有效订单。
- [ ] 支付失败后可安全重试，不产生重复扣款。
- [ ] Order Confirmation 不泄露他人订单信息。

### 7.5 账户

- [ ] 用户可注册、登录、退出和重置密码。
- [ ] 密码重置 Token 一次性、有限期且不可从日志读取。
- [ ] 用户只能访问自己的订单和地址。
- [ ] 游客订单可按批准的规则关联到后续注册账户。

### 7.6 履约与通知

- [ ] 运营人员可为一个订单创建全部或部分 Shipment。
- [ ] 发货后订单履约状态正确更新。
- [ ] 客户收到包含 Tracking Link 的发货邮件。
- [ ] 重复发货操作被阻止或明确要求确认。
- [ ] 物流 API 失败时订单数据保持一致并可重试。

### 7.7 退款

- [ ] 客服可选择订单行和数量执行部分退款。
- [ ] 退款金额不能超过尚未退款金额。
- [ ] Provider 退款成功后才将内部状态标记为成功。
- [ ] 重复提交不会产生二次退款。
- [ ] 可记录退款原因、操作人和时间。
- [ ] 客户收到退款通知邮件。

### 7.8 Admin

- [ ] 不同角色只能访问被授权功能。
- [ ] 商品上下架、库存调整和退款产生审计记录。
- [ ] 列表支持基本搜索、筛选和分页。
- [ ] 管理操作失败时显示错误且不产生半完成数据。

## 8. 非功能验收标准

### 8.1 性能

- [ ] 生产环境核心页面使用移动端网络条件完成性能测试。
- [ ] 首页、Collection、PDP 的 LCP 目标不高于 2.5 秒（75 分位）。
- [ ] CLS 目标不高于 0.1。
- [ ] INP 目标不高于 200ms。
- [ ] 商品图片不因原图尺寸造成明显布局偏移。

### 8.2 可用性与无障碍

- [ ] 核心购买流程可仅用键盘完成。
- [ ] 表单错误与对应字段关联。
- [ ] 文本与交互控件满足 WCAG 2.2 AA 的基础对比度要求。
- [ ] 焦点状态可见，Modal 有焦点约束与关闭机制。
- [ ] 不依赖颜色作为唯一状态提示。

### 8.3 安全

- [ ] 管理端启用强认证策略，生产建议 MFA。
- [ ] Stripe/PayPal/物流 Secret 不进入前端 Bundle。
- [ ] Webhook 验签、限流和幂等测试通过。
- [ ] Cookie 配置 HttpOnly、Secure、SameSite。
- [ ] 日志不记录密码、Token、完整支付信息和敏感个人数据。
- [ ] 依赖漏洞扫描无未接受的 Critical 问题。

### 8.4 可靠性与运维

- [ ] PostgreSQL 自动备份已配置，并完成一次恢复演练。
- [ ] 支付、订单、退款和物流错误进入监控。
- [ ] 后台任务支持重试，达到上限后可人工查看。
- [ ] 发布过程支持快速回滚到上一版本。
- [ ] 生产与测试环境数据、密钥完全隔离。

### 8.5 SEO 与分析

- [ ] sitemap.xml、robots.txt 和 canonical 正确。
- [ ] Product、Breadcrumb、Organization 结构化数据通过校验。
- [ ] 404 商品不被错误索引。
- [ ] GA4 至少采集 view_item、add_to_cart、begin_checkout、purchase、refund。
- [ ] purchase 事件不会因页面刷新重复上报。

## 9. 上线门槛

以下项目全部满足才可正式上线：

- P0/P1 缺陷清零。
- Stripe 生产账号与 Webhook 配置完成。
- 至少完成一次真实低金额支付、发货和退款全链路验证。
- 税务策略由经营主体确认。
- Shipping / Return / Privacy / Terms 文案经业务或法律顾问确认。
- 数据库备份、监控、告警和应急联系人已配置。
- 客服具备订单、退款和异常处理 SOP。

## 10. 待评审决策

- [ ] 是否允许未发货订单由客户自助取消，还是仅联系客服。
