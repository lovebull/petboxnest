## 可重复的样本

在仓库根目录执行：

```sh
node apps/backend/tools/email-client-fixtures.cjs
```

输出至新的 `/tmp/pbn-email-acceptance-*` 目录，包含 11 类模板、2 个边界场景的 HTML、EML 和 manifest。直接从当前源码渲染；不读取数据库或 .env，不触发业务事件，不发送邮件。示例金额、客户及验证码为虚构数据，操作链接指向 example.com。图片使用网站公开 Logo 测试远程加载，不代表商品图片比例已经验收。过期时间为固定测试日期。

EML 可用于支持打开邮件文件的客户端初步检查。**打开本地 EML 不等于真实投递验收**；尤其不能代替 Gmail 收件后的 HTML 处理。样本自带纯文本仅用于 MIME 样本，不表示生产发送链路已增加纯文本。

## 真实邮箱验收

1. 提供并授权测试收件地址；使用真实 Resend 配置发送标记 `[TEST ONLY]` 的样本 HTML，保持正式模板样式，不转发已有邮件，不触发真实订单、付款或退款。
2. 保存发送时间、Resend Message ID、样本 SHA256、客户端名称/版本、操作系统、截图和结果。敏感收件信息不提交仓库。
3. Gmail 网页与手机 App；Outlook 网页/新版及 Windows 经典版；Apple Mail macOS 与 iOS 分别验证，不能以其中一款替代全部。
4. 每个客户端检查浅色、深色、允许图片、禁止图片；移动端窄屏，桌面端正常与放大显示。
5. 发现问题后保留原截图，修复模板，重新生成并发送同场景，保存前后证据。不可只修改报告为通过。

| 检查项 | 通过条件 |
| --- | --- |
| 图片 | 正方形、横图、竖图的真实商品图片均不拉伸、不撑破；禁止图片时仍可理解商品和金额 |
| 按钮 | 文案完整、对比清晰、可点击，实际链接与备用链接一致 |
| 圆角 | 支持时显示圆角；不支持时方角可接受，但不能丢背景、裁文字或破坏间距 |
| 深色模式 | 标题、正文、验证码、金额和按钮可读，无白字白底或黑字黑底 |
| 布局 | 无横向滚动、遮挡、长链接溢出；长标题与售后消息换行正常 |
| 退款 | 累计 30 USD 与两条 20 / 10 USD 记录明确区分；无记录时不显示虚构金额 |
| 业务入口 | 样本只验目标一致性；正式流程使用独立测试账户验收真实链接及过期行为 |
